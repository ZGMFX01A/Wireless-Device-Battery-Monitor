# 单 EXE 交付与自动更新

应用交付契约是可直接运行的单个 `WirelessDeviceBatteryMonitor-vX.Y.Z.exe`，无需安装或解压目录。配置仍保存于 EXE 旁，托盘独占设备访问，设置窗口运行于独立进程。

## 方案核对与恢复范围

2026-10-01 核对自动更新重构后发现：`18dc1a7` 把标准构建从 PyInstaller `--onefile` 改为 `--onedir`，发布链路改为 Velopack Setup、Portable 和更新包，违反原交付契约。

- [Velopack Python 文档](https://docs.velopack.io/getting-started/python)明确要求 `--onedir`，不兼容 `--onefile`。
- [WinSparkle 标准更新流程](https://winsparkle.org/appendix/user-experience/)下载并启动安装器；用于便携 EXE 仍需自己实现文件替换。
- [PyUpdater](https://github.com/Digital-Sapphire/PyUpdater)已于 2022 年归档，不作为新增依赖。
- [tufup](https://github.com/dennisvang/tufup)可更新不同打包方式，但需要维护 TUF 签名元数据、密钥和更新文件部署。它是后续可评估的方向，本次没有证据证明它是保持现有发布与多进程生命周期的直接替代。

按用户已授权的回退条件，恢复旧的 GitHub Releases API + 整个 EXE 下载 + 进程外 PowerShell 替换与重启。恢复 `--onefile`、版本化资产名、GUI 子进程独立解压环境和旧版本回滚；移除 Velopack 依赖、启动钩子及打包步骤。

保留现有 Flet 桌面资源完整性检查、私有核心接入、构建时本地 VERSION 来源、手动发布 tag 解析与 GitHub 认证修复、按界面语言选择更新日志、设备刷新和蓝牙功能。历史版本说明保留原样。

## 更新边界与取舍

先使用 GitHub 官方资产地址；官方不可用时沿用旧方案的镜像回退。所有下载都必须通过 GitHub 元数据中的大小和 SHA-256 校验，缺少摘要即明确失败。安装器不得当作便携 EXE 原地替换，只有应用资产名可进入自动更新。

下载完成后由独立 PowerShell 进程等待托盘退出、替换 EXE、重启；失败时保留或恢复旧 EXE。设置进程通过退出请求通知托盘，保留 PyInstaller onefile 父进程的收尾语义。

独立审查发现旧脚本在第一次移动当前 EXE 前没有进入恢复保护。已把停止宿主后的完整流程纳入异常恢复，为第一次移动增加有限重试，并按移动是否完成决定回滚，避免误删既有目标文件。实际执行生成的 PowerShell 脚本，验证首次移动持续失败、安装移动失败、首次移动暂时失败及目标冲突四种情况；故障注入仅拦截移动与重启动作，不停止真实应用。

恢复后的客户端只接受单 EXE 发布资产。已经使用 Velopack 安装版或 Portable 目录版的用户需要手动下载单 EXE，并自行关闭旧版；本次不提供安装目录迁移，不改已发布的 GitHub 资产。

必须修改：更新器、打包与发布配置、入口与配置中的更新钩子、GUI/托盘调用、对应文案及下载说明。需要验证：下载校验和回退、路径安全、GUI 子进程环境、单 EXE 实际构建与启动。仍待调查：无；真实在线更新须在新单 EXE 版本发布后验收。

## 验收

构建契约检查在修改前明确失败（`standard build no longer produces a single portable EXE`），修改后通过。运行更新器及受影响公开壳测试，实际构建单 EXE，并只携带该 EXE 执行既有 `--smoke-test`。更新执行涉及文件替换与进程退出，完成后对冻结 diff 进行独立审查。未经用户要求不提交、推送或发布。

## 完整更新链路加固

2026-10-01 完整审查复现慢网络无总截止时间、GUI 检查提前超时、多个任务争用下载文件、替换进程失败仍关闭应用、安装前内容变化未被拦截、启动失败没有回滚，以及错误版本资产被选中。用户已授权修复。

保持单 EXE 与托盘/GUI 分离，不引入安装器或在线签名基础设施。借鉴 Velopack 的应用级互斥和临时下载隔离，以及 TUF 的严格目标元数据验证。

下载采用统一检查预算、每个来源及整次下载截止时间、读取空闲超时和持续低速检查，GUI 提供取消。阻塞网络调用由有界后台线程执行；截止或取消后线程不能再写下载文件，迟到响应会关闭。IPv4 优先只用于本模块的连接，不修改全局 socket 解析器。只接受与 tag 精确匹配的便携资产以及有效大小和 SHA-256。

Windows 命名信号量让手动、自动与替换进程共享更新互斥。每次更新使用独立事务目录。替换程序打开同一信号量并核验落盘下载后发出 ready；调用方确认 ready 后交接互斥并通知宿主退出。交接之前的失败保留应用运行，取消不进入替换阶段。

替换程序在安装前及安装后再次验证 SHA-256，有限等待旧进程退出和有限重试移动文件。新进程通过一次性环境 token，在配置、设备管理器与托盘初始化完成后写启动确认。没有确认、提前退出或超时则恢复旧 EXE；确认成功后才删除备份。ConfigManager 不再在初始化时删除备份。替换结果记录在 EXE 旁，失败重启后可通过日志与托盘提示观察。

必须修改：更新器与事务协议、入口启动确认及退出处理、GUI 更新/取消流程、托盘启动回执、旧版清理钩子、更新文案及回归测试。需要验证：真实跨进程互斥和 PowerShell 文件替换、损坏/变更内容拒绝、交接失败、启动失败回滚、成功提交、慢网络/取消和单 EXE 打包启动。仍待调查：真实用户网络质量；修复不能保证 GitHub 或公共镜像始终可用。

检查总预算为 12 秒；下载总预算为 240 秒，每个来源最多 90 秒，读取空闲超过 5 秒或连续 15 秒低于 1 KiB/s 即失败并尝试下个可用来源。替换程序就绪等待最多 8 秒，旧进程优雅退出等待 20 秒，新版本启动确认等待 60 秒。新版本以 CREATE_SUSPENDED 暂停创建，纳入 Windows Job Object 后才恢复执行，失败时结束整个进程组再恢复文件；安装失败的同一版本暂停自动重试，仍可在设置中手动重试。

回归覆盖真实跨进程更新互斥、交接后互斥持续、移动失败和暂时占用、错误内容、安装时内容变化、进程提前退出和无启动确认、正常启动提交、取消与迟到网络响应，以及 GUI 忙碌和重试。测试使用隔离目录与无副作用子进程；真实线上旧版本到已发布新版本的更新仍需发布后验收。

独立审查指出先启动后加入 Job 会漏掉抢先创建的 onefile 子进程。修复采用 Windows CreateProcessW 暂停创建、归入 Job、恢复线程的顺序；真实父子进程测试验证无启动确认时两者均退出，旧版本文件恢复并触发重新启动。依据：[Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[进程创建标志](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags)。
